# 靶点尽调 · 商业计划书

**面向肿瘤药物研发的靶点证据审计平台**

浙客松 AI+X 破界黑客松 · 天猫 OPC 孵化赛道

---

## 一、项目概述

靶点尽调为肿瘤药物研发的**靶点选择环节**提供自动化证据审计。输入一个候选靶点和目标癌种，
系统从七个公开数据源汇集证据，**自动识别并解释互相矛盾的证据**，输出包含冲突清单、
七维证据矩阵与治疗窗判断的结构化审计报告。

一句话定位：**在投入之前，先看清靶点的风险。**

## 二、问题

抗肿瘤药物从临床前研究到最终获批的整体失败率长期超过 90%。在临床阶段失败的项目中，
相当一部分并非源于化合物优化不足，而是在靶点选择阶段未能识别出结构性风险。

这些风险有一个共同特征：**它们表现为证据之间的矛盾，而不是证据的缺失。**

以我们实际运行中的发现为例。CDKN2A 在胰腺癌患者中改变频率极高，但在胰腺癌细胞系中敲除
并不影响生长——临床证据说"很重要"，模型证据说"打它没用"。这个矛盾在只看任一指标时
都不会显现。如果不加辨别地立项，可能投入数年才发现方向错了。

### 现有工作流的三个缺口

目前研究者的常规做法是在多个数据库之间分别检索、人工汇总成表、凭经验取舍。这个过程：

1. **效率低**：完成一个靶点的多源证据整理通常需要数日；
2. **不可复现**：判断依赖个人经验，没有记录与复核机制，换个人可能得出不同结论；
3. **矛盾被掩盖**：人工汇总时方向相反的结论往往被平均化或选择性忽略。

### 现有工具的定位

靶点证据整合领域已有成熟平台，例如由欧洲分子生物学实验室与多家国际药企联合建设的
Open Targets。其核心定位是**证据聚合与关联评分**：输出"该靶点与该疾病的相关程度如何"，
并以并列方式呈现各来源的证据。

这留下三处空白：**不处理证据矛盾**（并列呈现，不作判断）、**不回答选择性问题**
（以单一疾病为锚点，缺乏跨癌种与跨组织的对照）、**不涉及结论可靠性评估**。

## 三、解决方案

### 产品形态

输入：候选靶点名称 + 目标癌种。

输出：一份审计卡，包含

- **冲突清单**：所有方向矛盾的证据组合，附机理解释与建议的验证实验
- **七维证据矩阵**：肿瘤依赖性、跨癌种选择性、临床相关性、正常组织暴露、
  人类遗传学耐受性、经验性在靶毒性、成药性
- **治疗窗判断**：综合肿瘤侧与正常侧证据的结论
- **完整溯源**：每一条结论都附带原始数据源链接

刻意不输出综合评分。靶点决策需要的是取舍依据，而评分会把相互矛盾的信息平均化，
恰好掩盖决策所需的关键差异。

### 三种交付形态

| 形态 | 面向 | 特点 |
|---|---|---|
| 在线工作台 | 所有用户 | 零安装，打开即用，可搜索筛选 |
| 命令行工具 | 研究者 | 审计任意靶点，可脚本化批量运行 |
| 接口 | 企业 | 嵌入客户已有的研发工作流 |

## 四、为什么是现在

**数据已经不是瓶颈。** DepMap、TCGA、gnomAD、HPA、ChEMBL、openFDA 六个关键数据源
全部开放且维护良好。单个靶点的可用证据在数量上已相当充足。

**瓶颈已经转移到判断环节。** 真正的困难是不同来源方向相反时该信谁。

**大模型让这件事第一次变得可行，但必须受约束。** 直接让模型读原始数据找矛盾是不可复现的，
而且会稳定地编造。我们的做法是：规则层负责定位矛盾（纯函数、可单测），
模型只负责解释已检出的矛盾，且解释范围限定在预定义的原因词表内。
**换模型不改变矛盾是否存在。**

## 五、技术实现与验证

### 已完成并经过真实数据验证

- 七个数据源全部接入，覆盖 2554 个细胞系、34 个谱系
- 七条冲突检测规则在真实数据上**全部触发过**
- 37 项单元测试通过
- 运行时零第三方依赖（仅用 Python 标准库），部署成本极低

### 真实运行结果（节选）

| 靶点 / 癌种 | 系统判断 | 触发的冲突 |
|---|---|---|
| KRAS / 胰腺癌 | 治疗窗待确认，安全边界待确认 | R1、R5 |
| CDKN2A / 胰腺癌 | 模型体系存疑，需要换策略，成药路径不明 | R3、R7、R4 |
| EGFR / 肺腺癌 | 安全边界待确认，抑制深度需严格控制 | R5、R6 |
| TP53 / 肝癌 | 抑制深度需严格控制 | R6 |
| BRCA2 / 胰腺癌 | 选择性不足 | R2 |

### 运行中发现并修正的问题

这些问题只有跑真实数据才会暴露，也都已在代码中记录成因：

1. 只统计点突变会严重低估肿瘤抑制基因——CDKN2A 在胰腺癌中的改变频率由 16.2% 修正为 40.0%；
2. ChEMBL 靶点匹配不能只靠名称，否则有上市药的 EGFR 会被判成"无成药路径"；
3. 流行病学数据库的上报总数不能取聚合查询的字段，否则"有副作用"会被读成"没有副作用"。

## 六、目标用户

**第一梯队：高校与科研院所的靶点研究课题组。**
立项前需要快速判断一个靶点值不值得投入。目前靠学生手工查库，耗时长且不可复核。
这是最容易触达、也最能产生口碑的群体。

**第二梯队：早期生物医药公司的立项团队。**
管线决策容错空间小，需要系统化的证据审计记录，也需要能拿给投资人和内部评审看的材料。

**第三梯队：CRO 与医药投资机构的尽调团队。**
需要快速判断一个标的的技术合理性，审计报告的格式天然契合尽调场景。

## 七、竞争定位

我们**不重造证据聚合层**，而是站在既有基础设施之上构建其未覆盖的判断层。

| | 现有整合平台 | 靶点尽调 |
|---|---|---|
| 回答的问题 | 这个基因和这个疾病有关联吗 | 这个靶点比替代选择好多少 |
| 输出 | 关联分数 + 证据列表 | 冲突清单 + 治疗窗判断 |
| 对矛盾证据 | 并列呈现，不作判断 | 主动检出并解释成因 |
| 视角 | 锚定单一疾病 | 肿瘤侧 × 正常侧对撞，跨癌种比较 |
| 形态 | 供查阅的门户 | 可嵌入工作流的工具 |
| 可靠性 | 无自我验证机制 | 以已知结局的历史靶点回溯检验 |

差异化的核心不是数据更全，而是**把"矛盾"本身当作产品对象**。

## 八、商业模式

**免费层：在线工作台。** 公开的审计结果集，任何人可浏览。作用是建立可信度与获客——
用户在看到真实审计卡之前，不会相信一个自动化工具的判断。

**订阅层：课题组版。** 自定义靶点、批量审计、报告导出、私有部署。
面向高校课题组与小型研发团队，按年订阅，定价在千元级。

**项目层：定制审计报告。** 为药企立项会议、投资尽调提供针对特定靶点组合的深度报告。
按靶点数量计费。

**接口层：能力输出。** 把审计能力以 API 形式嵌入客户已有的研发工作流或数据平台。

优先做订阅层与项目层：前者验证产品是否被真实使用，后者验证结论是否有商业价值。

## 十一、风险与应对

**数据源可用性。** 系统依赖六个第三方公开接口。已实现单数据源故障降级——
任一数据源不可用不会导致审计失败，对应维度会标记为"证据不足"而非静默缺失。
同时具备缓存重放能力，离线环境也能复现完整结果。

**结论准确性。** 系统不输出无依据的判断：证据覆盖不足时只报"证据不足"，
不给正面结论；模型输出必须通过校验才会采用，否则降级到规则层。
后续通过回溯检验量化准确率。

**合规风险。** 系统定位为面向科研的靶点证据整理工具，
不输出诊断、治疗或用药建议，全部使用公开数据，不涉及患者隐私。

**商业化难度。** 医药研发决策链条长、保守。策略是先服务课题组积累口碑与可信度，
再向企业端延伸，不试图一开始就切入核心决策。
